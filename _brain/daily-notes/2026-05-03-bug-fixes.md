# Bug Fix Session — Post-QA (2026-05-03)

> Fixed all 8 bugs discovered during the [[2026-05-03-test-execution|full system test run]]. Worked in severity order: high first, then medium, then low.

## Bug 1: `/apply/track` returns 500 on not-found + no rate limit

**Root cause:** `ApplicationTrackingController::track()` called `->withInput()` on a `View` object. That method only exists on `RedirectResponse` — the View's `__call` magic method tried to handle it and crashed with `Undefined array key 0`. Also, no `throttle` middleware on the route.

**Fix:**
- Changed `return view()->withErrors()->withInput()` to `return back()->withErrors()->withInput()`
- Added `throttle:5,1` middleware to `POST /apply/track`

**Files:** `app/Http/Controllers/ApplicationTrackingController.php`, `routes/web.php`

---

## Bug 2: Duplicate applications allowed

**Root cause:** No uniqueness checks on `email` or `national_id` in `RegistrationController::store()` or `CreateApplication::handle()`.

**Fix:** Added closure validators on both fields:
- Email: blocks if exists in `users` table (already enrolled), or in `applications` with status `pending`/`initially_approved`/`accepted`
- National ID: blocks if exists in `applications` with status `pending`/`initially_approved`/`accepted`
- Rejected applications allow resubmission

**Files:** `app/Http/Controllers/RegistrationController.php`

---

## Bug 3: ApproveApplication crashes on email collision + admin create student crash

**Root cause:** `ApproveApplication::handle()` called `User::create()` without checking if email already exists. Admin student create form had no `unique` validation on email or national_id.

**Fix:**
- Added email pre-check in `ApproveApplication::handle()` with Arabic error message
- Added `unique:users,email` rule on `user_email` field in `StudentResource` form (with `ignoreRecord` for edit)
- Added `unique:students,national_id` rule on `national_id` field (with `ignoreRecord` for edit)
- Added `->required()` to all essential personal data fields (mother_name, birth_date, birth_place, gender, marital_status, nationality, national_id, residence, permanent_address, study_type)
- Arabic validation messages on all unique rules

**Files:** `app/Actions/ApproveApplication.php`, `app/Filament/Resources/Students/StudentResource.php`, `tests/Feature/TransferCourseEditTest.php` (fixture updates)

## Bug 4: Validation messages show raw `validation.required`

**Root cause:** App locale was `ar` but no `lang/ar/validation.php` file existed. Framework validation rules fell through to raw translation keys.

**Fix:** Created `lang/ar/validation.php` with full Arabic translations for all standard Laravel validation rules.

**Files:** `lang/ar/validation.php` (new)

---

## Bug 5: Re-scoring an F grade doesn't resolve the warning

**Root cause:** `GradeObserver::updated()` only fired `handleApproval()` when `status` changed to `Approved`. In-place edits of grade values while status stayed `Approved` were ignored — the letter recomputed correctly but warnings and GPA weren't re-evaluated.

**Fix:** Added a second condition in `updated()` — also fires `handleApproval()` when `coursework_grade`, `final_grade`, `total`, or `letter` change while status is already `Approved`.

**Files:** `app/Observers/GradeObserver.php`

---

## Bug 6: Sample data hyphens fail validation + `name_en` not saved

**Root cause:** English name regex `^[a-zA-Z\s]+$` rejected hyphens and apostrophes. Also, `CreateApplication::handle()` never included `name_en` in the `Application::create()` call.

**Fix:**
- Relaxed regex to `^[a-zA-Z\s\-']+$` in both `RegistrationController` and `StudentResource`
- Added `'name_en' => $data['name_en'] ?? null` to `CreateApplication::handle()`

**Files:** `app/Http/Controllers/RegistrationController.php`, `app/Filament/Resources/Students/StudentResource.php`, `app/Actions/CreateApplication.php`

---

## Bug 7: Double GPA recalc + 2N audit rows

**Root cause:** `ViewCourseGrades` called `$calculator->recalculateStudentGPA()` directly in 3 actions (approve, change_status, approve_all), but the `GradeObserver` already triggers the same recalc on status→Approved. Also, `gpa` in `AuditObserver::WATCHED_FIELDS` for Student created redundant audit rows.

**Fix:**
- Removed all 3 direct `GradeCalculationService` calls from `ViewCourseGrades` (kept `notifyGradePublished` — observer doesn't handle that)
- Removed `'gpa'` from `AuditObserver::WATCHED_FIELDS` for Student
- Removed unused `GradeCalculationService` import

**Files:** `app/Filament/Resources/Grades/Pages/ViewCourseGrades.php`, `app/Observers/AuditObserver.php`

---

## Bug 8: Faculty cross-course access

**Root cause:** `ViewMyCourse` and `ViewCourseGrades` resolved records via Livewire route-model binding, bypassing `MyCourseResource::getEloquentQuery()`'s `faculty_id` scope. A faculty member could access another faculty's course by typing the URL directly.

**Fix:**
- Added `boot()` ownership check on `ViewMyCourse` — aborts 403 if `faculty_id !== auth()->id()`
- Added `boot()` ownership check on `ViewCourseGrades` — same check, only for faculty role (admin/secretary can view all)
- Added faculty ownership check to `CourseOfferingPolicy::view()` and `::update()` — faculty can only view/update their own course offerings

**Files:** `app/Filament/Resources/Faculty/Pages/ViewMyCourse.php`, `app/Filament/Resources/Grades/Pages/ViewCourseGrades.php`, `app/Policies/CourseOfferingPolicy.php`
