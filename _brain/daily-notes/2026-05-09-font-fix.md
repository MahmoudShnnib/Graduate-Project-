# 2026-05-09 — Noto Kufi Arabic Font Fix

## Context

Continued from the 2026-05-08 session. The Noto Kufi Arabic font had been downloaded to `public/fonts/Noto_Kufi_Arabic/` and added to the three CSS files (`app.css`, `admin/theme.css`, `student/theme.css`) via `@font-face` + `@theme { --font-sans: ... }`. After `npm run build`, the user reported no visible change.

---

## Investigation

Checked the built CSS output — both Filament theme files had:
- `@font-face` for Noto Kufi Arabic ✓
- `--font-sans: "Noto Kufi Arabic", ...` ✓
- `--default-font-family: var(--font-sans)` ✓

CSS looked correct, so the problem lay elsewhere. Used tinker to inspect the running panel:

```
$panel->getFontFamily()     → 'Inter Variable'
$panel->getFontPreloadHtml() → preloads Inter woff2 from /fonts/filament/filament/inter/...
```

==Root cause: Filament v5 uses its own `--font-family` CSS variable (set via inline `<style>` from PHP), not Tailwind's `--font-sans`. Our CSS override never touched that variable.==

> [!bug] The trap
> `@theme { --font-sans: 'Noto Kufi Arabic' }` updates Tailwind utility classes only. Filament's body font is driven by `--font-family`, set server-side by `filament()->getFontFamily()`, injected as an inline style — which beats any linked stylesheet.

---

## Fix

1. Created `public/css/noto-kufi-arabic.css` with a single `@font-face` declaration pointing to the TTF.
2. Added `->font('Noto Kufi Arabic', url: asset('css/noto-kufi-arabic.css'), provider: LocalFontProvider::class)` to **both** `AdminPanelProvider` and `StudentPanelProvider`.
3. Ran `php artisan optimize:clear`.

Verified with tinker: `getFontFamily()` now returns `'Noto Kufi Arabic'` and `getFontHtml()` emits the local CSS `<link>` instead of the Inter stylesheet.
