# 2026-05-14 — Shield permissions restored + seeder self-heal wired in

## What happened

User noticed `/admin/shield/roles` showed `0` in the الصلاحيات column for every role, while the rest of the panel kept working normally. Diagnosed as the `permissions` table being empty — a recurrence of [[../bugs-and-fixes/2026-04-20-filament-shield-roles-broken]].

## What was done

1. Ran `php artisan shield:generate --all --panel=admin --no-interaction` → 192 permissions across 17 policies, 29 entities.
2. Ran `php artisan db:seed --class=RolesAndPermissionsSeeder` → roles re-mapped, user roles repaired.
3. Wired self-heal into `RolesAndPermissionsSeeder::run()` so the seeder will regenerate permissions automatically if the table is empty when it starts.
4. Logged the recurrence + the explanations for `student` / `panel_user` empty counts in [[../bugs-and-fixes/2026-05-14-shield-permissions-table-empty]].

## Verification

```

  student: 0      (intentional — student panel uses middleware, not Shield)
  panel_user: 0   (intentional — HasPanelShield fallback role)
```

## Files touched

- `database/seeders/RolesAndPermissionsSeeder.php` — `Artisan` import + self-heal block.
- 15 `app/Policies/*.php` — regenerated by `shield:generate`, formatted by Pint. No behavior change.
- `_brain/bugs-and-fixes/2026-05-14-shield-permissions-table-empty.md` — new bug note with the full diagnosis and rationale.

## Next steps

- None immediate. The seeder is now self-sufficient against future `migrate:fresh` runs.
