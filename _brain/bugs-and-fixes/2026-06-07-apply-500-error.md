# /apply POST returns 500 on production

## Symptoms

Applicant completes the full `/apply` form → **500 Internal Server Error** on submit (no validation message).

## Likely causes (production)

1. **Upload directory not writable** — Dokploy volume at `storage/app/public` may be root-owned; `store('applications', 'public')` fails silently (`throw => false` on public disk) or throws on DB insert with bad path.
2. **Missing `whats_app_otps` migration** — would 500 on OTP check if migrations behind (less likely after entrypoint migrate).
3. **Uncaught DB/notification exception** — previously bubbled as generic 500 with no user message.

## Fix (code)

- `docker/entrypoint.sh` — `mkdir -p storage/app/public/applications storage/logs` + `chown` + `chmod ug+rwX`.
- `RegistrationController::store()` — full post-validation try/catch, explicit failed-upload errors, `Log::error`.
- `Application` model — `birth_date` date cast.
- `.env.example` — `LOG_STACK=single,stderr` for Docker visibility.
- Dokploy env updated with `LOG_STACK=single,stderr`; redeploy triggered.
- **Requires git push to `main`** for entrypoint/controller changes to reach production (auto-deploy).

## Immediate server workaround (no redeploy)

```bash
docker exec -it $(docker ps -q -f name=cet-graduate-app) sh -c '
mkdir -p /var/www/storage/app/public/applications
chown -R www-data:www-data /var/www/storage
ls -la /var/www/storage/app/public/
'
```

Then read the actual error:

```bash
docker exec $(docker ps -q -f name=cet-graduate-app) tail -50 /var/www/storage/logs/laravel.log
```
